How I work

The flow from the QA guide book I wrote for our squads. QA takes part in every phase, from the first requirement to the release in production.

QA starts here, before any code

  1. 01

    Requirement & design

    Join context gathering, design review, and grooming. Flag cases the design or PRD misses, dependencies, and the impact on existing features.

  2. 02

    Sprint planning

    Estimate testing effort, ask to split stories that are too big, and make sure estimates leave room to fix QA feedback.

  3. 03

    During the sprint

    A QA subtask on every story, test cases in a shared template, execution against acceptance criteria, and bugs filed as feedback tickets.

  4. 04

    Sprint review

    Present the test summary and demo each story from its test cases: the happy path first, then edge cases.

  5. 05

    Release preparation

    Sanity and targeted regression on staging, a release test report, the go-ahead to PM and Tech Lead, then sanity and smoke tests in production.

any time production breaks

Hotfix handling

When an issue comes in through Customer Support: confirm it is a real bug, offer users a workaround, test the fix on staging with sanity and smoke tests, then check it again in production.
